# Что лежит на столе и куда это ставить: восприятие → сцена MoveIt → pick&place

Сценарий «рука на столе» (`ros2 launch cart_xarm_bringup arm_table_gz.launch.py`).
Три ноды пакета `xarm_grasping` и интерфейсы пакета `xarm_grasping_msgs`.

> С 2026-11-09 на столе **семь предметов**: к четырём формам добавлены повторы — ещё два куба (`cube_2`, `cube_3`) и цилиндр (`cylinder_2`), чтобы проверять номера «куб 1/2/3» и диалог «этот?». Список — `cart_xarm_bringup/config/arm_table_objects.yaml`.
> С 2026-11-02 на столе **четыре предмета**: `cube`, `parallelepiped`, `rect_plate`, `cylinder` (раньше
> было 8 мелких коробок и цилиндров). В `/objects` их `id` вида `cube_0`, `cylinder_0`. Правила классов
> по размерам — `config/objects.yaml`, название по картинке (нейросеть) — поле `detector_label`, см.
> [book/RECOGNITION_OPENVINO.md](book/RECOGNITION_OPENVINO.md) и [book/MODEL_TRAINING.md](book/MODEL_TRAINING.md).
> Сам pick&place на новых предметах после замены набора не прогонялся.

```
/gripper_camera/points ─► object_perception ── /objects (DetectedObjectArray) ──┐
                           облако → стол → кластеры → форма → класс             │
                           action /detect_objects                               ▼
                                                                         scene_manager
config/objects.yaml (правила классов) ──────────────────────────────►    Planning Scene MoveIt:
config/place_zones.yaml (зоны) ─────────────────────────────────────►    объекты, стол, камера;
/vacuum_gripper/held ───────────────────────────────────────────────►    захват = прикрепить к link_tcp
                                                                          action /find_place_pose
                                                                          /place_zones/markers
                                                                                │
action /pick_place (object_id, zone) ─► pick_place_server ─── MoveIt (/move_action,
                                         detect → место → над объектом → вниз →   /compute_cartesian_path,
                                         вакуум → вверх → над зоной → вниз →      /execute_trajectory)
                                         отпустить → вверх → detect               + /vacuum_gripper/set
```

## 1. Восприятие — `object_perception.py`

Облако камеры гриппера переводится в `link_base` и обрабатывается функциями
`xarm_grasping/perception.py` (без ROS, можно тестировать отдельно):

1. **Стол** — плоскость около `table_height` (для стола 0.0), σ шума глубины.
2. **Кластеры** — ячейки 1×1 см, у которых медиана высоты выше max(1 см, 3σ);
   одиночные ячейки — шум.
3. **Форма** (по мотивам `shape_extraction.cpp` R2): выпуклая оболочка верхней
   части объекта → прямоугольник минимальной площади (коробка, с поворотом) и
   описанная окружность (цилиндр); побеждает меньший объём. Высота — медиана
   верхней грани.
4. **Класс** — правила `config/objects.yaml`: форма + размеры с допуском `tol`.
   Не подошло ни одно — класс = форма (`box` / `cylinder`), маркер красный.

Результат — `xarm_grasping_msgs/DetectedObjectArray` в `/objects` (раз в секунду и
по запросу) и маркеры `/objects/markers` (форма + подпись `id (уверенность)`,
размеры в см).

| Поле `DetectedObject` | Что |
|---|---|
| `id` | `<класс>_<n>`, сохраняется между распознаваниями (тот же класс в 5 см) |
| `label`, `confidence` | класс и уверенность 0..1 |
| `shape`, `dimensions` | `SHAPE_BOX` [L, W, H] / `SHAPE_CYLINDER` [H, R] |
| `pose` | центр; для коробки X вдоль длинной стороны |
| `grasp_pose` | центр верхней грани, присоска вниз |

Объект в присоске (пока вакуум держит) в `/objects` не попадает.

```bash
ros2 topic echo /objects
ros2 action send_goal /detect_objects xarm_grasping_msgs/action/DetectObjects "{update_scene: true}"
```

## 2. Сцена MoveIt — `scene_manager.py`

* объекты из `/objects` → `CollisionObject` в Planning Scene — MoveIt объезжает их;
* стол → `table` (верх на 3 мм ниже найденной плоскости — база руки стоит на нём);
* камера гриппера с кронштейном → прикреплённое тело на `link_eef` (её нет в
  модели MoveIt);
* вакуум схватил (`/vacuum_gripper/held`) → ближайший к присоске объект
  прикрепляется к `link_tcp`; отпустил → откреплён и остаётся там, где поставлен.

Это работает и при ручном захвате (кнопка в RViz), не только из `/pick_place`.

## 3. Куда ставить — зоны

`config/place_zones.yaml`: прямоугольники на столе (в `link_base`) и что в них
ставится (`accepts`: классы или категории из `objects.yaml`). Видны в RViz
(дисплей PlaceZones).

action `/find_place_pose` (`object_id`, `zone`): сетка точек в зоне (шаг
`search_step`), объект целиком в зоне, до других объектов ≥ `clearance`; из
свободных — ближайшая к центру зоны. Зона не задана — первая, которая принимает
класс объекта.

```bash
ros2 action send_goal /find_place_pose xarm_grasping_msgs/action/FindPlacePose "{object_id: cube_0}"
```

## 4. Взять и поставить — `pick_place_server.py`

```bash
ros2 action send_goal /pick_place xarm_grasping_msgs/action/PickPlace \
    "{object_id: cube_0}" --feedback               # зона по правилам
ros2 action send_goal /pick_place xarm_grasping_msgs/action/PickPlace \
    "{object_id: cylinder_0, zone: zone_cylinders}" --feedback
```

Шаги (feedback `stage`): `detect` → место в зоне (ищется ДО захвата) →
`plan_pregrasp` (MoveIt OMPL над объектом) → `approach` (прямо вниз до 5 мм над
верхом) → `grip` (ждём `/vacuum_gripper/ready`, вакуум, подтверждение `/vacuum_gripper/state`) → `lift` → `transfer`
(MoveIt над местом) → `lower` (низ объекта в 6 мм над столом) → `release` →
`retreat` → `detect`. Ошибка любого шага — `success: false` и причина; цель можно
отменить.

Требует MoveIt (`use_moveit:=true`, по умолчанию). Без окна RViz:
`use_rviz:=false` (аргумент добавлен в `xarm_moveit_config/_robot_moveit_common`).

## Подтверждение захвата: взяли или нет (симуляция и реальная рука одинаково)

Единый сигнал — топик **`/vacuum_gripper/state`** (`std_msgs/Bool`, `true` = предмет удерживается).
Его публикует тот узел, который соответствует вашему запуску; `pick_place_server` об этом не знает и
работает с обоими одинаково:

| | Симуляция | Реальная рука (xArm) |
|---|---|---|
| Узел | `vacuum_gripper_sim.py` | `vacuum_gripper_xarm.py` |
| Откуда `state` | объект приварен (подтверждено плагином Gazebo) | цифровой датчик давления захвата: `/xarm/get_vacuum_gripper` = 1 |
| Касание до включения вакуума | `/vacuum_gripper/ready` | нет (датчик работает только при включённом вакууме) |

`pick_place_server` проверяет `state` **трижды**: после включения вакуума (ждёт до `hold_confirm_s`, 1 с),
после подъёма и после переноса (перед опусканием). Нет подтверждения — вакуум выключается, действие
завершается `success: false` с причиной («захват не подтверждён…» / «предмет потерян при подъёме» / «…при переносе»).

**Реальная рука.** Запуск переходника: `ros2 run xarm_grasping vacuum_gripper_xarm.py` (нужен запущенный
драйвер `xarm_api`; параметры `ns`, `hardware_version` 1 = Plug-in / 2 = Contact, `grip_timeout`,
`idle_timeout`). Для `pick_place_server` включить `probe_with_vacuum:=true`: у реального захвата нет датчика
касания, поэтому вакуум включается **до** спуска, и рука опускается шагами, пока давление не станет «нормальным».

**Защита насоса.** Драйвер xArm сам вакуум не отключает ни по таймауту, ни при потере предмета. Поэтому
переходник выключает его сам: если вакуум включён дольше `idle_timeout` (8 с) без предмета; при потере связи с
драйвером; при выходе из узла (Ctrl+C, kill).

**Что проверено.** Переходник — на подмене драйвера без руки (`tools/fake_xarm_vacuum.py`): отказ без предмета,
успех с предметом, падение `state` при потере предмета, выключение по `idle_timeout`, выключение при выходе.
Взятие и перенос в симуляции — реальный прогон `/pick_place` (`rect_plate_0`), все три проверки прошли.
**Не проверено:** сама рука и датчик давления, ветка «предмет потерян» в `pick_place_server`, режим
`probe_with_vacuum` (нужна рука), значения `idle_timeout` и `hold_confirm_s` подобраны без железа.

## Команды текстом: «возьми куб 1» — `pick_by_name.py`

Узел для приложения: принимает название и номер, находит предмет и берёт его через `/pick_place`.
Запускается вместе с `arm_table_gz.launch.py` при `use_moveit:=true`.

**Куда писать и что видно**

| Что | Топик | Тип |
|---|---|---|
| Команда | `/pick_command` | `std_msgs/String` |
| Ответ человеку («беру куб 2», «этот куб?», «готово») | `/pick_status` | `std_msgs/String` |
| То же для программы (JSON: `state`, `text`, `class`, `number`, `object_id`) | `/pick_status_json` | `std_msgs/String` |
| Кадр камеры со стрелкой «этот?» (пока диалог открыт, обновляется раз в секунду; смотреть: `ros2 run rqt_image_view rqt_image_view /pick_by_name/image`) | `/pick_by_name/image` | `sensor_msgs/Image` |
| Стрелка и подпись в RViz | `/pick_by_name/marker` | `MarkerArray` |

```bash
ros2 topic pub --once /pick_command std_msgs/msg/String "{data: 'куб 1'}"
ros2 topic echo /pick_status          # смотреть ответы
```

**Команды**

| Написать | Что произойдёт |
|---|---|
| `куб 2`, `cube 2`, `пластина 1` | взять конкретный предмет по номеру |
| `куб` | если такой предмет один — берёт; если несколько — диалог «этот?» |
| `да` / `нет` | в диалоге: взять показанный / показать следующий |
| `стоп` | отменить диалог и текущее взятие |
| `список` | что есть на столе |

**Номера.** Номер — порядок среди предметов **этого класса** на столе: сначала меньшее `y`, при равных меньшее `x`
(система `link_base`). Пока предметы не двигают, номера те же; после перестановки считаются заново. В диалоге
номер показан на картинке и в RViz. Названия и синонимы лежат в `config/object_catalog.yaml` (добавили предмет —
добавьте и запись).

**Какой класс у предмета.** Берётся название от нейросети (`detector_label`), если её уверенность не ниже
`min_detector_score` (0.3), иначе класс по размерам из облака.

**Что проверено (2026-11-09).**
- Логика без симуляции (`tools/test_pick_by_name.py`, поддельные `/objects` с двумя кубами и поддельный `/pick_place`): 11 из 11
  проверок — номера, синонимы, отказ при неверном номере, неизвестное название, диалог «да / нет / больше нет», «стоп», «список».
- В симуляции: команда `куб` реально взяла и поставила куб (весь цикл `detect … retreat`, статусы пришли).
- Картинка со стрелкой: на реальном кадре камеры стрелка встала на нужное место (проверено на выдуманном втором кубе, сдвинутом на 12 см).
**Не проверено:** диалог на двух настоящих одинаковых предметах в сцене (в сцене один куб), запуск узла через
`arm_table_gz.launch.py` (правка launch внесена, но целиком не запускалась), работа через приложение (rosbridge и т. п.).
Подпись на картинке английская (`cv2` не рисует кириллицу), в RViz — русская.

## Сцена со многими объектами

Список объектов стола — `cart_xarm_bringup/config/arm_table_objects.yaml` (имя =
класс, форма, размер, место). После правки:

```bash
python3 src/r2_robot/cart_xarm_bringup/tools/gen_arm_table_scene.py   # мир + мост
```

Новый класс — добавить правило в `xarm_grasping/config/objects.yaml` (иначе
распознается как `box` / `cylinder`). Объекты отправляются по id из `/objects`
(`<класс>_<n>`); id держится, пока объект на месте, и переезжает вместе с ним,
если его унесла присоска.

## Ограничения

* Объекты видны только с камеры гриппера: распознавание — только из позы
  наблюдения (она же стартовая); из других поз сцена не обновляется.
* Соседние объекты ближе ~5 см иногда сливаются в один кластер (вероятно,
  «летающие» точки на перепадах глубины).
* Классы — по форме и размеру; объекты одной формы и размера не различаются
  (нужен цвет/нейросеть — следующий шаг).
* Захват — центр верхней грани, присоска вертикально; наклонённые/лежащие на боку
  объекты не обрабатываются.
* Тележка (`cart_xarm6_gz.launch.py`) этими нодами пока не пользуется.
