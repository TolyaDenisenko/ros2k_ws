## 3. Известные проблемы и ограничения

| # | Проблема | Статус / что делать |
|---|---|---|
| K1 | **Производительность.** На ноутбуке с Intel HD (Haswell) RTF ≈ 0.1–0.15 даже с `gripper_camera_preview:=true`. Полный режим 1280×800 — на ПК с дискретной GPU | запускать на мощном ПК; для отладки логики хватает и медленного. Если RTF < 0.8 на целевом ПК: `gripper_camera_preview:=true`, `rate` в `config/gemini335le.yaml` |
| K2 | **DetachableJoint приваривает объект сам при загрузке** (как только робот и `pick_box` есть в мире) | нода `vacuum_gripper_sim` сразу шлёт detach при старте (в логе предупреждение «плагин приварил объект при старте — отпускаю») |
| K3 | Присоска в gz — «логическая» (жёсткое соединение), не физика вакуума: нет потери удержания от массы/момента | приемлемо для M3; формулы удержания — док. 10 §3 |
| K4 | Контакт присоски с боксом после attach: коллизии чашки и коробки остаются и могут «дрожать» | следить в бенчмарке; при проблемах — слегка утопить TCP или отключить пару коллизий |
| K5 | MoveIt-модель без камеры → планировщик не знает про её габариты (корпус камеры выступает на ~9 см от оси) | док. 04 §7–8: пробросить `add_gripper_camera` в `moveit_configs_builder.py` + SRDF |
| K6 | `grasp_analyzer` ждёт цилиндр, `table_height` не передаётся (док. 09 A1–A9) | будет заменён в рамках M2 |
| K7 | Мир `xarm_gz_bringup` (рука без тележки, `cylinder_block.world`, у вас есть незакоммиченная правка) **не менялся**: там стол/объекты прежние, вакуума нет | при необходимости перенести сцену и плагины туда |
| K9 | **Опрокидывание тележки при подводе руки (наблюдалось 1 раз).** На слабом ПК (RTF≈0.1) после `arm_goto_tcp.py` к коробке контроллер прервал траекторию (`goal_time_tolerance`), а поза модели оказалась x=−0.52, z=0.86, наклон ≈53° — тележка опрокинулась/уехала. Причина **не установлена**: подозрение на столкновение руки (интерполяция в суставах из сложенной позы) со столом/коробкой, коробка при этом сдвинулась на 4.5 см | на мощном ПК: смотреть `ros2 topic echo /gz/robot_pose`; идти сначала в безопасную промежуточную позу над столом; `arm_goto_tcp.py` — грубая утилита без проверки коллизий, для рабочих захватов — MoveIt. Если подтвердится — закрепить тележку в мире на время манипуляции |
| K8 | Стартовая поза руки по умолчанию направляет камеру вбок; коробка перед тележкой (x=0.6) в кадр не попадает | для проверки камеры: `arm_goto_tcp.py` или `--arm_initial_positions` (см. CAMERA_VACUUM_SIM.md §4) |

## 5. Решения (почему так)

| Решение | Причина |
|---|---|
| Облако строит `depth_image_proc`, а не gz | система координат gz-облака зависит от версии gz-sensors; на железе тоже строится по выровненной глубине |
| Меши через `file://$(find …)`, не `package://` | gz-sim не резолвит `package://` для наших пакетов (так же сделаны меши тележки) |
| Парент-звено DetachableJoint = `link6` | в SDF fixed-суставы URDF схлопываются: присоска, `link_eef` и камера лежат внутри `link6` (проверено `gz sdf -p`) |
| Корень SDF-модели — `base_footprint` | TCP в мире = поза модели (gz) × TF `base_footprint → link_tcp` |
| Позы для проверки касания — отдельные PosePublisher (10 Гц), а не `pose/info` | полный `pose/info` (сотни поз на шаг) съедал ~70% CPU у приёмника |
| Стол сдвинут на x=1.05, `spawn` тележки не менялся | при `spawn_x=1.0` (док. 00, P7) тележка (±0.36 м) въехала бы в стол; так коробка в 0.6 м от базы руки |
| D555 пока не делаем | по запросу: сначала Orbbec |
