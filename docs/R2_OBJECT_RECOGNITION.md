# Распознавание объектов в R2 (OpenVINO): что у нас есть

Разбор того, как робот R2 узнавал, *что* лежит перед ним, и что из этого можно
взять в наш проект. Источник — архив `~/Downloads/Ros-r2/quasi_ros_r2`
(получен 2026-10-22, без истории git). Нужные пакеты частично скопированы в
[`docs/reference/quasi_ros_r2_grasp/`](reference/quasi_ros_r2_grasp/README.md).

> **Коротко.** В R2 распознавание собрано из двух половин. Нейросеть OpenVINO
> находит объект *на картинке* и даёт имя и рамку. Облако точек находит его
> *в пространстве* и даёт кластер, форму и позу. Связывает их простое правило:
> кластер принадлежит рамке, если не меньше половины его точек, спроецированных
> в кадр, попадают внутрь рамки. Код связки у нас есть. Самой нейросети, то есть
> модели и обёртки Intel, в архиве нет.

---

## 1. Зачем это нам

Наше восприятие (`object_perception`, см. [PICK_PLACE.md](PICK_PLACE.md))
различает объекты только по форме и размеру. Две одинаковые коробки с разным
содержимым для него — один класс. Это открытый пункт чек-листа §4:
«одинаковые по форме и размеру объекты не различаются».

R2 решал ровно эту задачу: геометрия говорит, *где* объект и *как* его взять,
нейросеть — *что* это. Цепочка геометрии у нас уже есть и проверена.
Недостающая половина — имя объекта по картинке.

## 2. Как это устроено в R2

```
                 /realsense/color/image_raw
                            │
              ┌─────────────▼──────────────┐
              │ openvino_image_object_server│  пакет dynamic_vino_sample
              │  (Intel ros2_openvino_toolkit)│  (в архиве его нет)
              │  модель model.xml/.bin, CPU │
              │  порог уверенности 0.6      │
              └─────────────┬──────────────┘
                 сервис /openvino_image_object_server/service
                 object_msgs/srv/DetectObject → ObjectsInBoxes
                 (имя, уверенность, рамка ROI в пикселях)
                            │
   /realsense/depth/color/points + camera_info
                            │
              ┌─────────────▼──────────────┐
              │ perception (lifecycle-нода)│  quasi_r2_perception
              │ action DetectObject         │
              │  1. спросить нейросеть       │
              │  2. сегментировать облако    │
              │  3. сопоставить кластер↔ROI  │
              │  4. подобрать примитив       │
              └─────────────┬──────────────┘
                 quasi_r2_msgs/Object[]: имя, кластер с нормалями,
                 коробка/цилиндр/шар + поза, опорная плоскость
                            │
                 find_grasp_service (GPD) → MoveIt pick
```

### 2.1. Нейросеть: `openvino_image_object_server`

Запускается из `quasi_r2_perception/launch/r2_perception.launch.py`,
настраивается `param/openvino_object_server.yaml`:

| Параметр | Значение | Что значит |
|---|---|---|
| вход | `ImageTopic` ← `/realsense/color/image_raw` | цветной кадр камеры |
| вывод | `RosService` | детекция по запросу, а не потоком |
| `infers.name` | `ObjectDetection` | детектор с рамками (тип сети в конфиге не указан, по формату — SSD-подобная) |
| `model` | `~/.local/share/quasi/object_detection_model/model.xml` | модель в формате OpenVINO IR (`.xml` + `.bin`) |
| `label` | `…/model.labels` | имена классов |
| `engine` | `CPU` | без GPU и NPU |
| `confidence_threshold` | 0.6 | ниже — отбрасывается |
| `rate` | 15 | кадров в секунду |

Рядом с моделью лежит ещё `model_objects.json`. Нода `perception` читает из
него форму каждого класса (`"shape": "box"` и т. п.): если в запросе форма не
задана, она берётся отсюда.

**Версия.** Сборка и установка (`quasi_r2_deployment`) ставят OpenVINO
**2021.4** в `/opt/intel/openvino_2021`. Это старый API Inference Engine; в
текущих выпусках OpenVINO его уже нет.

### 2.2. Связка: action `DetectObject`

`quasi_r2_msgs/action/DetectObject`:

```
vision_msgs/BoundingBox3DArray workspace   # где искать
float32 area_height -1                     # высота опорной поверхности (−1 — любая)
string  object_name                        # "" — без нейросети, "*" — все, иначе имя класса
uint8   shape_type                         # SolidPrimitive, 0 — только меш, 255 — автоопределение
---
Object[] objects
```

Шаги (`src/perception_detect_object_action.cpp`):

1. **Спросить нейросеть**, если `object_name` не пуст. Тайм-аут 10 с. Оставить
   детекции с нужным именем; если таких нет — goal прерывается.
2. **Сегментировать облако** (`object_segmentation.cpp`): обрезка по рабочей
   зоне, нормали, RANSAC-плоскости (горизонтальные — опоры), евклидова
   кластеризация (`cluster_tolerance 0.025`, от 100 точек). Берутся два кадра
   облака подряд.
3. **Сопоставить кластер и рамку** (`intersect_segmented_objects_with_roi2`):
   точки кластера переводятся в оптический кадр цветной камеры и проецируются
   в пиксели через `image_geometry::PinholeCameraModel`. Если доля попавших в
   рамку ≥ `min_roi_intersection` (0.5), кластер получает имя детекции.
   Есть параметр `reduce_roi` — сузить рамку к центру, если она шире объекта.
   При заданной `area_height` отбрасываются кластеры не на той высоте.
4. **Подобрать примитив** (`shape_extraction.cpp`): выпуклая оболочка на
   опорной плоскости → коробка минимальной площади с поворотом или цилиндр
   минимального радиуса, выбирается меньший объём. Плюс меш кластера.

Без нейросети (`object_name: ""`) действие возвращает все кластеры без имён.
Это ровно то, что сейчас делает наш `object_perception`.

## 3. Что у нас есть и чего нет

| Часть | Есть? | Где / комментарий |
|---|---|---|
| Код связки «рамка ↔ кластер» | ✅ | `docs/reference/quasi_ros_r2_grasp/quasi_r2_perception` (C++/PCL), оригинал в архиве |
| Сообщения `DetectObject`, `Object` | ✅ | `quasi_r2_msgs` там же |
| Конфиги детектора | ✅ | `param/openvino_object_server.yaml`, `param/perception.yaml` |
| **Модель** `model.xml` / `.bin` / `.labels` / `model_objects.json` | ❌ | на этом ПК нет `~/.local/share/quasi/`; лежит на самом R2 или у того, кто её обучал |
| **Обёртка Intel** `dynamic_vino_sample` + `object_msgs` | ❌ | исходников в архиве нет; это пакеты `ros2_openvino_toolkit` эпохи OpenVINO 2021 |
| OpenVINO на этом ПК | ❌ | ни системного, ни Python-модуля `openvino` |
| Список классов, на которых обучали | ❓ | неизвестен без `model.labels` |
| Датасет и скрипты обучения | ❓ | в архиве нет |

**Главное:** без файлов модели взять из R2 можно только идею и код связки.
Распознать что-либо «как R2» не получится.

## 4. Как это перенести к нам

### 4.1. Нейросеть: своя тонкая нода вместо `dynamic_vino_sample`

Переносить обёртку Intel нет смысла: она завязана на OpenVINO 2021.4, а у нас
Ubuntu 24.04 и Kilted. Проще своя нода на Python поверх современного OpenVINO
Runtime (пакет `openvino` из pip или apt-репозитория Intel). Модели IR из
2021.4 он, как правило, читает; если нет — модель переконвертируется из
исходника (ONNX и т. п.). Это нужно проверить на самой модели.

Нода:

- вход: `/gripper_camera/color/image_raw` (и позже передняя камера тележки);
- выход: `vision_msgs/Detection2DArray` (стандарт ROS, есть в Kilted) —
  имя класса, уверенность, рамка;
- работает по запросу или с невысокой частотой, на CPU.

### 4.2. Связка: дописать в `object_perception`, а не переносить C++

Наш `object_perception` уже делает шаги 2 и 4 (стол, кластеры, форма) на
numpy. Не хватает шага 3, а он короткий: спроецировать точки кластера в кадр
по `camera_info`, посчитать долю внутри рамки, присвоить имя при ≥ 0.5.
Поле для имени в `xarm_grasping_msgs/DetectedObject` уже есть (`label`), так что
интерфейс `/objects` и `/pick_place` не меняется. Класс из нейросети
дополняет классы по размеру из `config/objects.yaml`, а не заменяет их.

### 4.3. Симуляция: нейросеть не увидит наши кубики

Модель R2 обучена на реальных предметах. Зелёные коробки и цилиндры Gazebo
она не узнает. Для симуляции два пути, и они не исключают друг друга:

- **детектор-заглушка** по истине из Gazebo (`scene_markers` уже знает, где
  какой объект): проецирует известные объекты в кадр и публикует те же
  `Detection2DArray`. Так проверяется вся связка без нейросети;
- **реалистичные модели объектов** в мире (меши с текстурами настоящих
  предметов) — тогда настоящую модель можно гонять и в симуляции.

## 5. Вопросы, без которых дальше не двинуться

1. **Где файлы модели?** Нужна папка `~/.local/share/quasi/object_detection_model/`
   с робота R2: `model.xml`, `model.bin`, `model.labels`, `model_objects.json`.
2. **Какие объекты она знает** и подходят ли они для наших задач?
3. **Есть ли датасет и код обучения**, если придётся дообучать под наши предметы?
4. **На каком железе** будет работать распознавание на тележке (CPU, Intel GPU,
   NPU) — от этого зависит выбор устройства в OpenVINO.

## 6. Предлагаемый порядок

1. Получить файлы модели (вопрос 1), поставить OpenVINO Runtime, проверить, что
   модель загружается и даёт рамки на фотографии.
2. Нода детектора → `Detection2DArray`.
3. Шаг «рамка ↔ кластер» в `object_perception`.
4. Детектор-заглушка из истины Gazebo — проверить связку в сценарии «рука на
   столе».
5. Реалистичные объекты в мире или дообучение — по результатам вопросов 2–3.
