## 5. Решения (почему так)

| Решение | Причина |
|---|---|
| Облако строит `depth_image_proc`, а не gz | система координат gz-облака зависит от версии gz-sensors; на железе тоже строится по выровненной глубине |
| Меши через `file://$(find …)`, не `package://` | gz-sim не резолвит `package://` для наших пакетов (так же сделаны меши тележки) |
| Парент-звено DetachableJoint = `link6` | в SDF fixed-суставы URDF схлопываются: присоска, `link_eef` и камера лежат внутри `link6` (проверено `gz sdf -p`) |
| Корень SDF-модели — `base_footprint` | TCP в мире = поза модели (gz) × TF `base_footprint → link_tcp` |
| Позы для проверки касания — отдельные PosePublisher (10 Гц), а не `pose/info` | полный `pose/info` (сотни поз на шаг) съедал ~70% CPU у приёмника |
| Стол сдвинут на x=1.05, `spawn` тележки не менялся | при `spawn_x=1.0` (док. 00, P7) тележка (±0.36 м) въехала бы в стол; так коробка в 0.6 м от базы руки |
| D555 пока не делаем | по запросу: сначала Orbbec |
