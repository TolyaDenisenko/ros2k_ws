# Что лежит на столе и куда это ставить: восприятие → сцена MoveIt → pick&place

Сценарий «рука на столе» (`ros2 launch cart_xarm_bringup arm_table_gz.launch.py`).
Ноды пакета `xarm_grasping` и интерфейсы пакета `xarm_grasping_msgs`. Это справочник: какие
команды, топики и параметры есть и что проверено. Как всё устроено внутри — главы
[10](10-восприятие-объектов.md) (восприятие), [11](11-сцена-moveit.md) (сцена MoveIt),
[12](12-разметка-стола-и-зоны.md) (зоны), [13](13-pick-place.md) (pick&place).

**Что на столе.** С 2026-11-09 — **семь предметов**: четыре формы `cube`, `parallelepiped`,
`rect_plate`, `cylinder` и повторы `cube_2`, `cube_3`, `cylinder_2` (чтобы проверять номера
«куб 1/2/3» и диалог «этот?»). Список — `cart_xarm_bringup/config/arm_table_objects.yaml`. Имя
модели в Gazebo — не класс: класс в `/objects` дают правила по размерам
(`xarm_grasping/config/objects.yaml`), поэтому три куба — все `cube`, а их `id` — `cube_0`,
`cube_1`, `cube_2` (номер в id — порядок, в котором нода их впервые увидела). Название по
картинке (нейросеть) — поле `detector_label`, см. [RECOGNITION_OPENVINO.md](RECOGNITION_OPENVINO.md)
и [MODEL_TRAINING.md](MODEL_TRAINING.md). История: до 2026-11-09 было 4 предмета, до 2026-11-02 —
8 мелких коробок и цилиндров.

**Запуск.** Всё ниже работает при `use_moveit:=true` (по умолчанию). Для команд по названию и
осмотра нужна нейросеть — её надо включить явно (модель по умолчанию в launch — YOLOX на COCO,
наших предметов она не знает):

```bash
ros2 launch cart_xarm_bringup arm_table_gz.launch.py detector:=true \
    detector_model:=~/.local/share/quasi/models/sim_shapes_v3/model_fp16.xml detector_conf:=0.2
```

Без окна RViz: `use_rviz:=false`. Все аргументы — [RUN_SCENARIOS.md](RUN_SCENARIOS.md).

```
/gripper_camera/points ─► object_perception ── /objects (DetectedObjectArray) ──┐
/detections (нейросеть) ─► облако → стол → кластеры → форма → класс             │
                           action /detect_objects                               ▼
                                                                         scene_manager
config/objects.yaml (правила классов) ──────────────────────────────►    Planning Scene MoveIt:
config/place_zones.yaml (зоны) ─────────────────────────────────────►    объекты, стол;
/vacuum_gripper/held ───────────────────────────────────────────────►    захват = прикрепить к link_tcp
                                                                          action /find_place_pose
                                                                          /place_zones/markers
                                                                                │
/pick_command («куб 2») ─► pick_by_name ─► сервис /survey_objects ─► survey_objects
                                │            (осмотр под 45°)          └► /objects_refined
                                ▼                                                │
action /pick_place (object_id, zone) ─► pick_place_server ◄──────────────────────┘
                                         observe → detect → место → над объектом → вниз →
                                         вакуум + /vacuum_gripper/state → вверх → над зоной →
                                         вниз → отпустить → вверх → observe → detect
                                         MoveIt: /move_action, /compute_cartesian_path,
                                         /execute_trajectory; вакуум: /vacuum_gripper/set
```

## 1. Восприятие — `object_perception.py`

Облако камеры гриппера переводится в `link_base` и обрабатывается функциями
`xarm_grasping/perception.py` (без ROS, можно тестировать отдельно):

1. **Стол** — плоскость около `table_height` (для стола 0.0), σ шума глубины.
2. **Кластеры** — ячейки 1×1 см, у которых медиана высоты выше max(1 см, 3σ);
   одиночные ячейки — шум.
3. **Форма**: выпуклая оболочка верхней части объекта → прямоугольник минимальной площади
   (коробка, с поворотом) и описанная окружность (цилиндр); выбирается фигура, которую контур
   заполняет лучше (в R2 — меньший объём, у нас это оказалось неустойчиво, глава 10, §10.7).
   Высота — медиана верхней грани.
4. **Класс** — правила `config/objects.yaml`: форма + размеры с допуском `tol`.
   Не подошло ни одно — класс = форма (`box` / `cylinder`), маркер красный.
5. **Класс по картинке** (если запущена нейросеть, `detector:=true`): кластеру достаётся рамка из
   `/detections`, в которую попало ≥ 50% его точек → поля `detector_label`, `detector_score`.
   Геометрия всегда из облака.

Результат — `xarm_grasping_msgs/DetectedObjectArray` в `/objects` (раз в секунду и
по запросу) и маркеры `/objects/markers` (форма + подпись `id (уверенность)`,
размеры в см). Пока идёт осмотр (`/survey/active` = `true`, §6), периодическая публикация
пропускается.

| Поле `DetectedObject` | Что |
|---|---|
| `id` | `<класс>_<n>`, сохраняется между распознаваниями (тот же класс в 5 см) |
| `label`, `confidence` | класс по размерам и уверенность 0..1 |
| `shape`, `dimensions` | `SHAPE_BOX` [L, W, H] / `SHAPE_CYLINDER` [H, R] |
| `pose` | центр; для коробки X вдоль длинной стороны |
| `grasp_pose` | центр верхней грани, присоска вниз |
| `num_points` | сколько ячеек в кластере |
| `detector_label`, `detector_score` | класс по картинке и уверенность (пусто/0 — нет нейросети или рамки) |

Объект в присоске (пока вакуум держит) в `/objects` не попадает.

```bash
ros2 topic echo /objects
python3 src/r2_robot/cart_xarm_bringup/tools/show_objects.py     # то же таблицей
ros2 action send_goal /detect_objects xarm_grasping_msgs/action/DetectObjects "{update_scene: true}"
```

## 2. Сцена MoveIt — `scene_manager.py`

* объекты из `/objects` → `CollisionObject` в Planning Scene — MoveIt объезжает их;
* стол → `table` (верх на 3 мм ниже найденной плоскости — база руки стоит на нём);
* камера гриппера с кронштейном — уже в самой модели MoveIt (launch передаёт
  `add_gripper_camera:=true`), `scene_manager` её не добавляет;
* вакуум схватил (`/vacuum_gripper/held`) → ближайший к присоске объект (не дальше
  `attach_radius`, 8 см) прикрепляется к `link_tcp`; отпустил → откреплён и остаётся там, где
  поставлен.

Это работает и при ручном захвате (кнопка в RViz), не только из `/pick_place`.

## 3. Куда ставить — зоны

`config/place_zones.yaml`: прямоугольники на столе (в `link_base`) и что в них
ставится (`accepts`: классы или категории из `objects.yaml`). Сейчас две зоны:
`zone_boxes` (категория `box`: кубы, параллелепипед, пластина) и `zone_cylinders`. Видны в RViz
(дисплей PlaceZones).

action `/find_place_pose` (`object_id`, `zone`): сетка точек в зоне (шаг `search_step`, 1 см),
коробка вдоль или поперёк зоны, объект целиком в зоне, до контуров других объектов ≥ `clearance`
(4 см); из свободных — плотной укладкой рядами от ближнего к базе конца зоны. Зона не задана —
первая, которая принимает класс объекта (`label`, по размерам).

```bash
ros2 action send_goal /find_place_pose xarm_grasping_msgs/action/FindPlacePose "{object_id: cube_0}"
```

Вместимость: пять коробок нынешней сцены в `zone_boxes` (38×20 см) помещаются только впритык —
при сортировке всего стола последней, скорее всего, места не хватит (прикидка, не проверено;
глава 12, §12.7).

## 4. Взять и поставить — `pick_place_server.py`

```bash
ros2 action send_goal /pick_place xarm_grasping_msgs/action/PickPlace \
    "{object_id: cube_0}" --feedback               # зона по правилам
ros2 action send_goal /pick_place xarm_grasping_msgs/action/PickPlace \
    "{object_id: cylinder_0, zone: zone_cylinders}" --feedback
```

Шаги (feedback `stage`): `observe` (поза наблюдения) → `detect` (свежее распознавание; если
есть свежий осмотр — геометрия из `/objects_refined`, §6) → `transfer` «ищу место в зоне»
(место ищется ДО захвата) → `plan_pregrasp` (MoveIt OMPL над объектом, +10 см) → `approach`
(прямо вниз до 5 мм над верхом) → `grip` (до касания `/vacuum_gripper/ready` шагами по 3 мм, не
глубже 2.5 см; вакуум; подтверждение `/vacuum_gripper/state`, §5) → `lift` → `transfer` (MoveIt
над местом) → `lower` (низ объекта в 6 мм над столом) → `release` → `retreat` → `observe` →
распознавание. Ошибка любого шага — `success: false` и причина, рука уходит вверх и в позу
наблюдения; цель можно отменить.

| Параметр | По умолчанию | Что |
|---|---|---|
| `observe_pose` | `[0.30, 0.0, 0.40]` | присоска в позе наблюдения (`link_base`) |
| `approach_height`, `grasp_gap`, `place_drop` | 0.10, 0.005, 0.006 | подлёт, зазор над верхом, высота отпускания, м |
| `probe_step`, `probe_depth` | 0.003, 0.025 | шаг и предел спуска до касания, м |
| `probe_with_vacuum` | `false` | реальная рука: вакуум во время спуска (§5) |
| `hold_confirm_s` | 1.0 | ожидание подтверждения захвата, с |
| `use_refined` | `true` | брать геометрию из `/objects_refined` |
| `refined_match_radius`, `refined_max_age` | 0.04, 600.0 | предмет из осмотра не дальше 4 см и не старше 600 с |
| `velocity_scaling`, `accel_scaling`, `planning_time` | 0.3, 0.3, 5.0 | скорость/ускорение MoveIt, время планирования |

Подробно по шагам и почему так — [глава 13](13-pick-place.md).

## 5. Подтверждение захвата: взяли или нет (симуляция и реальная рука одинаково)

Единый сигнал — топик **`/vacuum_gripper/state`** (`std_msgs/Bool`, `true` = предмет удерживается).
Его публикует тот узел, который соответствует вашему запуску; `pick_place_server` об этом не знает и
работает с обоими одинаково:

| | Симуляция | Реальная рука (xArm) |
|---|---|---|
| Узел | `vacuum_gripper_sim.py` | `vacuum_gripper_xarm.py` |
| Откуда `state` | объект приварен (подтверждено плагином Gazebo) | цифровой датчик давления захвата: `/xarm/get_vacuum_gripper` = 1 |
| Касание до включения вакуума | `/vacuum_gripper/ready` | нет (датчик работает только при включённом вакууме) |

`pick_place_server` проверяет `state` **трижды**: после включения вакуума (ждёт до `hold_confirm_s`, 1 с),
после подъёма и после переноса (перед опусканием). Нет подтверждения — вакуум выключается, действие
завершается `success: false` с причиной («захват не подтверждён…» / «предмет потерян при подъёме» / «…при переносе»).

**Реальная рука.** Запуск переходника: `ros2 run xarm_grasping vacuum_gripper_xarm.py` (нужен запущенный
драйвер `xarm_api`; параметры `ns`, `hardware_version` 1 = Plug-in / 2 = Contact, `grip_timeout`,
`idle_timeout`). Для `pick_place_server` включить `probe_with_vacuum:=true`: у реального захвата нет датчика
касания, поэтому вакуум включается **до** последнего спуска, и рука опускается шагами, пока давление не
станет «нормальным».

**Защита насоса.** Драйвер xArm сам вакуум не отключает ни по таймауту, ни при потере предмета. Поэтому
переходник выключает его сам: если вакуум включён дольше `idle_timeout` (8 с) без предмета; при потере связи с
драйвером; при выходе из узла (Ctrl+C, kill).

**Что проверено (2026-11-09).** Переходник — на подмене драйвера без руки (`tools/fake_xarm_vacuum.py`):
отказ без предмета, успех с предметом, падение `state` при потере предмета, выключение по `idle_timeout`,
выключение при выходе. Взятие и перенос в симуляции — реальный прогон `/pick_place` (`rect_plate_0`), все три
проверки прошли. **Не проверено:** сама рука и датчик давления, ветка «предмет потерян» в `pick_place_server`,
режим `probe_with_vacuum` (нужна рука), значения `idle_timeout` и `hold_confirm_s` подобраны без железа.

## 6. Осмотр стола с разных сторон — `survey_objects.py` (2026-11-13)

**Зачем.** В момент взятия камера слепая: она на ~7 см выше присоски и не видит ближе 0.25 м. Где
предмет и что это, надо знать до спуска. Из позы наблюдения камера смотрит почти сверху: куб сверху —
квадрат, цилиндр — круг, высокие предметы закрывают соседей. Поэтому перед взятием рука проводит
камеру вокруг всех предметов под углом 45°.

**Как.** Сервис `/survey_objects` (`std_srvs/Trigger`): рука из позы наблюдения → 5 точек по дуге 140°
вокруг центра предметов, наклон 45°, 0.35–0.45 м (IK `/compute_ik`, движение `/move_action`) → обратно.
В каждом ракурсе рамки нейросети сопоставляются с предметами (проекция габарита, IoU ≥ 0.3), классы
голосуют: побеждает класс с наибольшей суммой уверенности, итоговая уверенность = сумма / число ракурсов,
где предмет был в кадре. Результат — `/objects_refined` (те же id, класс в `detector_label`/`detector_score`),
ход — `/survey/status`, голоса по ракурсам (JSON) — `/survey/votes`. Во время осмотра `object_perception`
не обновляет `/objects` (флаг `/survey/active`): с наклонных ракурсов в кадр попадает сама рука, и в сцене
MoveIt появлялся ложный объект на основании руки (рука после этого не могла вернуться — так и нашли).

Нужны MoveIt и нейросеть (`detector:=true`): без `/detections` голосовать нечему.

**Что дало (симуляция, `tools/check_survey_accuracy.py`, сравнение с позами из Gazebo):**

| | Вид сверху | После осмотра |
|---|---|---|
| Класс куба (3 куба) | названо 1–2 из 3, уверенность 0.2–0.3 | все три — «cube», 3–4 вида из 5 согласны |
| Центр предмета | 0.1–2.9 мм (пластина до 6.5) | **не лучше**: объединение облаков 3–7 мм, медиана по ракурсам 2.8 мм в среднем |
| Размеры | ошибка 8–23 мм | объединение облаков **раздувало** на 15–40 мм |

Поэтому **геометрия по умолчанию остаётся из вида сверху** (параметр `geometry`, по умолчанию `top`);
объединение облаков всех ракурсов — `geometry:=merge`, для опытов на настоящей камере. Причина раздувания:
облака ракурсов совмещаются хорошо (верх предметов совпадает с правдой в пределах 1–2 мм), но на наклонных
видах точки на границе предмета и стола («летящие» пиксели) тянутся наружу. В симуляции глубина идеальная,
и вид сверху уже точен до ~2 мм — выигрывать по положению там нечего. **На настоящей камере** (шум глубины,
блики, предметы вплотную) это не проверено: возможно, там осмотр по положению поможет — это и стоит
измерить первым делом на железе. Итого сейчас осмотр в основном уточняет **класс**.

`pick_place_server` берёт геометрию из `/objects_refined`, если предмет там есть (§4, `use_refined`);
при `geometry:=top` она совпадает с видом сверху.

Параметры `survey_objects`: `views` 5, `arc_deg` 140, `elevation_deg` 45, `min_dist`/`max_dist`
0.35/0.45 м, `settle` 1.0 с, `min_iou` 0.3, `geometry` `top`, `velocity_scaling` 0.4,
`detections_topic` `/detections`.

**Сколько стоит.** Осмотр — около 30–40 с (5 ракурсов). Полный цикл «куб 2 → осмотр → взять →
поставить» в симуляции — 58 с. Ракурс, куда рука не достаёт, пропускается (бывает 4 из 5).

```bash
ros2 service call /survey_objects std_srvs/srv/Trigger       # осмотр вручную
ros2 topic echo /survey/status                               # ход и итог
# точность против правды Gazebo (GZ_PARTITION — как у симуляции, если задан):
python3 src/r2_robot/cart_xarm_bringup/tools/check_survey_accuracy.py
```

## 7. Команды текстом: «возьми куб 1» — `pick_by_name.py`

Узел для приложения: принимает название и номер, находит предмет и берёт его через `/pick_place`.
Запускается вместе с `arm_table_gz.launch.py` при `use_moveit:=true`.

**Куда писать и что видно**

| Что | Топик | Тип |
|---|---|---|
| Команда | `/pick_command` | `std_msgs/String` |
| Ответ человеку («осматриваю стол…», «беру куб 2», «этот куб?», «готово») | `/pick_status` | `std_msgs/String` |
| То же для программы (JSON: `state`, `text`, `class`, `number`, `object_id`) | `/pick_status_json` | `std_msgs/String` |
| Кадр камеры со стрелкой «этот?» (пока диалог открыт, обновляется раз в секунду; смотреть: `ros2 run rqt_image_view rqt_image_view /pick_by_name/image`) | `/pick_by_name/image` | `sensor_msgs/Image` |
| Стрелка и подпись в RViz | `/pick_by_name/marker` | `MarkerArray` |

```bash
ros2 topic pub --once /pick_command std_msgs/msg/String "{data: 'куб 1'}"
ros2 topic echo /pick_status          # смотреть ответы
```

**Команды**

| Написать | Что произойдёт |
|---|---|
| `куб 2`, `cube 2`, `пластина 1` | осмотр (§6), затем взять конкретный предмет по номеру |
| `куб` | осмотр; если такой предмет один — берёт; если несколько — диалог «этот?» |
| `да` / `нет` | в диалоге: взять показанный / показать следующий |
| `стоп` | отменить диалог и текущее взятие |
| `список` | что есть на столе (без осмотра) |

**Перед каждой командой с названием** узел вызывает осмотр `/survey_objects` (параметр
`survey_before_pick`, по умолчанию `true`; около 30–40 с). Нет сервиса или осмотр не удался — работает по
виду сверху.

**Номера.** Номер — порядок среди предметов **этого класса** на столе: сначала меньшее `y`, при равных меньшее `x`
(система `link_base`). Пока предметы не двигают, номера те же; после перестановки считаются заново. Номер
«куб 2» и id `cube_1` — разные вещи: id даёт `object_perception`, номер считает `pick_by_name`. В диалоге
номер показан на картинке и в RViz. Названия и синонимы лежат в `config/object_catalog.yaml` (добавили класс —
добавьте и запись; там же можно задать зону `zone` для класса).

**Какой класс у предмета** (по порядку):
1. итог осмотра из `/objects_refined`, если его уверенность ≥ `min_refined_score` (0.15);
2. иначе название от нейросети сверху (`detector_label`), если уверенность ≥ `min_detector_score` (0.3);
3. иначе класс по размерам из облака (`label`).

**Что проверено.**

## 8. Сцена со многими объектами

Список объектов стола — `cart_xarm_bringup/config/arm_table_objects.yaml` (имя модели, форма, размер,
место). После правки:

```bash
python3 src/r2_robot/cart_xarm_bringup/tools/gen_arm_table_scene.py   # мир + мост
```

Ещё один предмет **уже известной формы и размера** (как `cube_2`) — только строка в списке и генератор.
Новый класс — добавить правило в `xarm_grasping/config/objects.yaml` (иначе распознается как
`box` / `cylinder`), запись в `config/object_catalog.yaml` (для команд текстом) и класс в датасет/модель
нейросети ([MODEL_TRAINING.md](MODEL_TRAINING.md)). Объекты отправляются в `/pick_place` по id из `/objects`
(`<класс>_<n>`); id держится, пока объект на месте, и переезжает вместе с ним, если его унесла присоска.

## 9. Ограничения

* Сцена (`/objects`) обновляется только из позы наблюдения: из других поз камера видит стол частично.
  Осмотр (§6) ездит по другим позам, но только голосует по классу (и, при `geometry:=merge`, пересчитывает
  геометрию) — в `/objects` и сцену MoveIt его ракурсы не попадают.
* Соседние объекты ближе ~5 см иногда сливаются в один кластер (вероятно,
  «летающие» точки на перепадах глубины).
* Одинаковые предметы (одной формы и размера) различаются только по положению — номером «куб 2»; по цвету
  или надписи — нет.
* Куб — самый слабый класс у нейросети `sim_shapes_v3` (уверенность сверху ~0.2–0.3); осмотр это исправляет
  в симуляции, на реальных кадрах не проверено.
* Захват — центр верхней грани, присоска вертикально; наклонённые/лежащие на боку
  объекты не обрабатываются.
* Тележка (`cart_xarm6_gz.launch.py`) этими нодами пока не пользуется.
